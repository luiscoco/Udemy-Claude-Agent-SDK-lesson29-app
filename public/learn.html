01

Compare the six explicit modes

Run default, dontAsk, acceptEdits, plan, auto and bypassPermissions against a fixed Read/Write task in a disposable directory. Compare the requested option with the actual mode reported by the SDK.

02

Count callbacks and verify files

Default can send the unapproved Write to the denying callback. dontAsk rejects unresolved approval without a callback. acceptEdits can approve the eligible local write. Native results, PostToolUse events and host file checks establish the outcome.

03

Review before a live mode switch

The plan-to-edit experiment pauses after the first real result. Review that result, approve or reject it, then observe the awaited setPermissionMode acknowledgement. Only an approved switch releases a second message on the same Query.

04

Keep earlier rules and hooks in view

Bypass requires the explicit TypeScript opt-in and still respects earlier deny/ask rules and hooks. The bounded deny experiment scopes an Edit rule to the exact classroom output. This app exposes only Read and Write and never launches shell commands.

05

Observe auto and omitted defaults honestly

Auto is model- and deployment-dependent. Its action result is not evidence that a classifier reviewed that particular Write. The omitted experiment records the actual starting mode. Current docs say newer SDK/headless runs default to default, which differs from the supplied slide and some type comments.

06

Understand subagent inheritance

Current docs keep a parent plan mode restrictive even when a child requests acceptEdits; only default/dontAsk parents can apply eligible definition overrides. A child cannot enable bypass. This is a source-linked reference topic here; the app launches no subagents.
